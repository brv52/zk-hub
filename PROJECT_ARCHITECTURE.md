# zk-votingHub Project Documentation

## 1. Project Overview
**zk-votingHub** is a decentralized, privacy-preserving voting platform. It utilizes Zero-Knowledge Proofs (ZKPs) to decouple voter eligibility from voter identity. This ensures that while only eligible participants can cast votes (Proof of Membership), their specific identity remains anonymous on the public ledger.

## 2. Technical Architecture
The system is designed with a modular architecture separating the off-chain cryptographic workload from the on-chain verification and state management.

### Core Components

#### A. Main zk-Hub (Orchestrator)
-   **Role**: The central smart contract system managing the election lifecycle.
-   **Responsibilities**:
    -   Proposal management (creation, active periods).
    -   Vote tallying and state storage.
    -   Nullifier tracking to prevent double-voting.
    -   Integration with Verifiers to validate transactions.

#### B. Verifiers (Cryptographic Shield)
-   **Role**: Standalone contracts responsible solely for mathematical verification of ZK proofs.
-   **Component: `POM_verifier`**:
    -   Specific verifier for **Proof of Membership**.
    -   Validates that a proof submitted by a user corresponds to a valid leaf in the eligibility Merkle Tree.

#### C. Client/Relayer
-   **Role**: Off-chain agent.
-   **Responsibilities**:
    -   Generates the ZK proof locally (inputs: private key, Merkle path).
    -   Constructs the transaction payload.

## 3. Tech Stack
-   **Blockchain Framework**: Hardhat (TypeScript) - used for compilation, testing, and deployment.
-   **Smart Contracts**: Solidity (`.sol`).
-   **ZK Circuits**: Circom - for defining the arithmetic circuits and constraints.
-   **Proving System**: Groth16 or Plonk (via SnarkJS).
-   **Testing**: Mocha & Chai - for unit and integration testing.
-   **Utilities**: `ts-node` for script execution.

## 4. Core Files Description

### `/verifiers` Directory
This directory houses the verification logic, isolated from the main business logic to ensure modularity and ease of updates.

#### `verifiers/POM_verifier`
Located at: `/home/borov/thesis/verifiers/POM_verifier/`

*   **`hardhat.config.ts`**:
    *   Configuration entry point for the verifier's Hardhat environment. Defines Solidity compiler versions and network settings tailored for the verifier contracts.

*   **`contracts/Verifier.sol`** (Inferred):
    *   The core Solidity contract, typically auto-generated by SnarkJS.
    *   Contains the `verifyProof(a, b, c, input)` function.
    *   Stores the Verification Key (alpha, beta, gamma, delta points) in bytecode or storage.

*   **`scripts/deploy.ts`** (Inferred):
    *   Script to deploy the `Verifier` contract to the target network.

### `/zk-votingHub` (Main Logic)
*Note: Conceptual description of the main hub files.*

*   **`contracts/VotingHub.sol`**:
    *   The primary interface for users.
    *   Maintains the `mapping(uint256 => bool) nullifiers` to enforce one-person-one-vote.
    *   Calls `IPOMVerifier.verifyProof(...)` before processing a vote.

*   **`circuits/membership.circom`**:
    *   The circuit definition file.
    *   Inputs: `privateKey`, `merklePath`, `merkleRoot`.
    *   Output: `nullifierHash`, `root`.
